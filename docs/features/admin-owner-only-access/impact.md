**Risks**

- **The rules deploy needs the deploy account to hold Firebase Rules Admin.** Likelihood high until the owner grants it, cost low (the step fails, hosting has already deployed). Intent §7, story Assumption 13. Carried: D-15 and OQ-1.
- **Rules are project-wide.** A rules deploy from anywhere other than `master` would replace the live rules. Carried: D-14 (only `deploy-production` deploys rules) and E2E-21.
- **Emulator versus production rules engine.** The proof runs the emulator's engine; production is Google's. The constructs used (`request.auth`, `resource.data`, equality, `||`) are the documented common subset, but nothing here has run against the live database. Carried: OQ-2; the owner's own check after the first deploy (intent §7).
- **A change to the rules that opens the database is silent.** A future edit to `firestore.rules` that weakens a rule must fail a test: E2E-01 to E2E-13 each assert both the accepted and the refused side, so a deny-all or an allow-all file fails at least one. Carried: the rows themselves.
- **Port 8080 in use** on a developer machine stops the emulator from starting. Likelihood low. Carried: Step 1 Stop-if.
- **Stale emulator data.** The emulator keeps documents in memory while it runs, and `reuseExistingServer` reuses a running one. Carried: D-09 (each test uses documents with unique ids and never depends on an empty database).

**Cleared**

- No client Firestore code is added, so the Firebase library's Firestore module does not reach any bundle and the public pages stay Firebase-free (`admin-sign-in` E2E-13 still holds).
- `firebase.json` `hosting` is not edited, so Invariant 2 (`trailingSlash`) is safe; E2E-22 asserts it.
- No new dependency, environment variable or secret: `firebase-tools` was approved and installed by `admin-sign-in`; the workflow only references the existing secret name.
- The owner's email never appears: rules match on user ID only; E2E-20 greps for it.

**Before merge** — the cheapest checks that catch the real bugs (each is an `E2E-` row): the signed-out, other-account and placeholder writes are all refused while the owner's is accepted (E2E-01 to E2E-05); a draft is unreadable to the public and to another account (E2E-07, E2E-08); the deploy job has the rules step after hosting and the staging job has none (E2E-21); the two owner ID places agree (E2E-19); the existing sign-in and smoke specs still pass (Step 3 Verify).
