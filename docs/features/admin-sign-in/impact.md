**Risks**

- **R1 — the emulator is now part of every Playwright run.** If it fails to start (no network for `npx` resolution of a missing binary, a port 9099 clash), `site-smoke.spec.ts` fails too. `playwright.config.ts:24-28` is the only webServer today. Likelihood low, cost medium (the e2e gate stops). Check: Step 1 runs `site-smoke.spec.ts`. Carried to Decision D-11 (`reuseExistingServer` keeps a developer's own running emulator) and Step 1's Stop-if.
- **R2 — the committed web config holds placeholders.** The real `apiKey` and `appId` are in the Firebase console and are not known to the pipeline; inventing them would be wrong. Live sign-in fails (and shows "Sign-in was not completed.") until the owner pastes them. Likelihood certain, cost low (a Human-only item; intent §7 already defers the live sign-in check to the owner). Carried to Decision D-05 and Open Questions OQ-1.
- **R3 — a public page starts loading the SDK.** A stray import of `src/lib/firebase/*` outside `AdminPanel.tsx` would put the library in the home page. Likelihood low, cost high (intent §5). Carried to TS-12 and E2E-13.
- **R4 — `firebase-tools` is large.** CI runs `npm ci`, so the install grows. Likelihood certain, cost low; accepted in intent §4.
- **R5 — hydration mismatch.** Reading `localStorage` or the Firebase user during the first render would differ from the prerendered HTML (Invariant 4's cousin). Carried to Decision D-09 (first render is the loading state; the account is read only inside the auth callback).
