**Risks**

- R-1 (ListEditor default path drifts for Experience and Projects): `addLabel` is read in one place; a wrong default would rename the add control on two shipped screens. Likelihood low, cost medium. Carried: Step 2 Verify re-runs both specs; D-09.
- R-2 (the image list cannot be read, so the chooser shows only `None` while a stored badge is an uploaded address): the address shows as text in the path field and is saved unchanged. Likelihood medium for an unfilled owner, cost low. Carried: D-13, BR-04d, E2E-13.
- R-3 (the `certifications` collection can hold documents an earlier spec wrote): `e2e/admin-owner-only-access.spec.ts` seeds `certifications/e2e-05` and `certifications/e2e-10` (a `name` field only; the loop at lines 140 and 197-203 covers the collection). They may stay in the shared emulator. Carried: `ownerSession` clears `certifications` and `images` first and `certificationFromData` reads them as empty text, so they cannot reach a row.
- R-4 (a stale tab adds a certification at a position another tab already used): two certifications can share a position and sort by id. Likelihood very low (one editor), cost low. Carried: D-04 (last save wins).

**Cleared**

- No new rule, index or emulator setting: `firestore.rules:31-34` already covers the collection; queries are whole-collection reads with client sorting, so no composite index.
- Public pages cannot carry the editor: it is imported only by `AdminPanel.tsx`, which only the panel route imports (`src/app/bright-warm-greenhouse/page.tsx`); E2E-17 checks it.
- No `<img>`, no `next/image`, no new CSS token, no new package, no new variable.
- The word `email` appears in none of the new files, so `admin-sign-in` E2E-15's search stays green.
