## 1. Business analysis — BA

### 1.1 Purpose

The owner wants to keep the work and education history current without opening the code. This feature gives the admin panel its first list editor: choosing "Experience" in the menu shows the saved entries, newest first by default, and lets the owner add an entry, edit it, move it up or down one place, and delete it after confirming. An entry has a year, a title, a company, a duration, a description and a list of detail lines; the first five are required. Nothing is prefilled from today's site, so the first time the list is empty. It does not change what visitors see on the public site (phase 2). This is also the pattern the projects, certifications and tech stack editors repeat: the same list, the same "Add entry", "Edit", "Move up", "Move down", "Delete" and "Confirm" controls, the same failure messages, so the shared part is built once and the Experience editor only says what its fields are.

### 1.2 Actors & preconditions

- **Owner:** the single Google account whose Firebase user ID is in the rules and in the panel's owner constant. Saving, moving and deleting work only for them once the ID is filled in.
- **Unfilled owner:** the owner signed in while the user ID is still the placeholder; the panel treats them as the owner for reading, shows the saving-off notice, and every write is refused by the rules (`admin-owner-only-access` D-06). The list itself loads, because `experience` is publicly readable.
- **Other account:** any other signed-in Google account; the panel shows the not-allowed screen and never the menu or the list.
- **Visitor (signed out):** sees only the sign-in control.
- Preconditions met by hand (intent §7): the owner's user ID in the rules and the panel constant. No automated row depends on them; every row runs against the local emulators.

### 1.4 Data touched

One collection of the database, `experience`: one document per entry holding the five texts, the detail lines (a list of texts), the entry's place in the list (`position`, a number) and the time of the last write. The editor reads the whole collection (publicly readable by the rules), adds a document, updates the content fields of one, updates only the place of the entries a move changes, and deletes one. It reads nothing from the signed-in account and uses no browser storage.

## 2. Technical specification — SA

### 2.1 Approach

Two shared layers and one configuration. `src/lib/admin/list.ts` is pure and generic: the entry type (`ListEntry<T>` with `id`, `position`, `content`), the shared wording, ordering (`sortEntries`, `topPosition`), the one-step move (`moveEntry`, `changedPositions`) and the two message builders. `src/lib/firebase/list.ts` is the generic store over one collection (`createListStore`): load, add, update, reorder in one batch, remove, each write under a 10 s timeout. `ListEditor.tsx` is a generic client component that owns everything a list editor does (the list, the add and edit form shell with Save and Cancel, Move up and Move down, the in-row confirm-delete, the messages, the busy guard); it is told the heading, the store, how to label an entry, how to start an empty one, how to check one, and how to draw its fields. The Experience editor is only that configuration: `src/lib/admin/experience.ts` (types, texts, check, tolerant read, label), `src/lib/firebase/experience.ts` (the store bound to the `experience` collection) and `ExperienceEditor.tsx` (the five fields and the detail lines). The projects, certifications and tech stack editors will copy the same three-file configuration. The rules need no change: `firestore.rules` already lets anyone read and only the owner write `experience/{id}`. `AdminPanel` renders the editor for the "Experience" item on the allowed screen only, and two earlier specs' placeholder tests move to the "Projects" item, which stays a placeholder.

### 2.3 Data model

```ts
// src/lib/admin/list.ts (pure: no firebase, no window)
export type ListEntry<T> = { id: string; position: number; content: T };
export type FieldErrors = Record<string, string | undefined>;     // keyed by field name
export type ListCheck<T> = { ok: true; content: T } | { ok: false; errors: FieldErrors };
export type ListMove = "up" | "down";
export type ListFailure = "save" | "move" | "delete";
export const UNPOSITIONED: number;                                // Number.MAX_SAFE_INTEGER

// src/lib/admin/experience.ts (pure)
export const EXPERIENCE_COLLECTION: string;                       // "experience"
export type ExperienceContent = {
  year: string; title: string; company: string; duration: string; description: string;
  details: string[];                                              // detail lines, in order
};
```

Firestore: collection `experience`, one document per entry, a new unique string id per entry, fields exactly `year`, `title`, `company`, `duration`, `description` (strings), `details` (array of strings), `position` (a number, integer valued) and `updatedAt` (a number: `Date.now()` at the last write, milliseconds). The list is shown by `position` ascending (a smaller number is higher), ties by id, a missing or non-number `position` last. A new entry gets `smallest position − 1` (0 when the list is empty). A move renumbers the displayed list 0 to n−1 and writes only the entries whose number changed. `experience` holds no other kind of document.

### 2.6 Non-functional notes

- Static export holds: no server, route or generated param is added; the editor is a client component reached only through `AdminPanel`, and Firestore is touched only inside effects and handlers, never at import or render.
- Public pages stay Firebase-free (E2E-31).
- Internal admin panel for one owner: no autosave, no draft, no conflict check, no field-length limit, no pagination; long text wraps.
- Tokens only for colour: `--surface-alt`, `--surface`, `--border`, `--border-strong`, `--foreground`, `--muted`, `--accent-rose`, `--radius-md`.
- Accessibility: every control is a native input, textarea or button reached by keyboard; each error is linked to its field with `aria-describedby`; the confirmation is a labelled group.
