## 1. Business analysis — BA

### 1.1 Purpose

The owner wants to use their own pictures on the portfolio without putting files in the code. This feature gives the admin panel an "Images" screen: the owner uploads a PNG, JPEG, WebP or SVG of up to 5 MB, sees every uploaded image listed with a preview, its original name and its size (newest first), copies an image's public address, and deletes an image after confirming. It also adds the file-storage rules that make the owner the only account able to upload or delete, refuse anything over 5 MB or that is not one of those four image types, and keep everything refused until the owner has filled in their user ID; and the database rule that keeps the list of uploaded images readable and changeable by the owner alone. It does not pick an uploaded image inside any editor, and it does not show uploaded images on the public site.

### 1.2 Actors & preconditions

- **Owner:** the single Google account whose Firebase user ID is in the rules and in the panel's owner constant (story Assumption 16).
- **Visitor (signed out):** may open an uploaded image by its address; may not upload, delete or see the list.
- **Other account:** any other signed-in Google account; same as a visitor for images, and shown no menu by the panel.
- **Unfilled owner:** the owner signed in while the user ID is still the placeholder; the panel treats them as the owner for reading only (`admin-owner-only-access` D-06).
- Preconditions the owner meets by hand (intent §7, story Assumption 18): the Blaze plan, the budget alert, the default storage bucket, and filling in the user ID in three places. No automated check depends on them; every row runs against the local emulators.

One collection of the database, `images`, holding one entry per uploaded file (original name, stored path, public address, type, size, created time), readable and writable by the owner only. ## 2. Technical specification — SA

### 2.1 Approach

Two new rule sets form the boundary: `storage.rules` (public read of one file at a time, no listing, owner-only create and delete of files under `images/`, at most 5 MB, PNG/JPEG/WebP/SVG only, the same owner placeholder as the database rules) and an owner-only `images` match added to `firestore.rules`. `firebase.json` and Playwright gain the Storage emulator on `127.0.0.1:9199`, and the existing `deploy:rules` script is extended so the live job's one rules step also publishes storage. The panel gains an "Images" menu item. Selecting it mounts a client component that reads the `images` collection (newest first), uploads a file to Storage, then writes its list entry, and deletes the file and then the entry; all of it runs through three small client modules that load Firebase's Firestore and Storage only inside the panel's own chunks. The accept/refuse decision, the size text and the stored path are pure functions in `src/lib/admin/images.ts`, which Playwright imports directly. The spec drives the emulators over REST for every rule row and drives the real popup sign-in for the screen rows. The saving-off notice and its tests are updated so the owner is told to fill in both rules files.

### 2.3 Data model

```ts
// src/lib/admin/images.ts (pure: no firebase, no window)
export const MAX_IMAGE_BYTES: number;                 // 5 * 1024 * 1024 = 5242880
export const ALLOWED_IMAGE_TYPES: readonly string[];  // "image/png", "image/jpeg", "image/webp", "image/svg+xml"
export const IMAGE_MESSAGES: { ... };                 // the exact texts of D-10
export type ImageRecord = {
  id: string;           // document id and the stem of the stored file name (a UUID)
  name: string;         // the owner's original file name
  storagePath: string;  // "images/<id>.<ext>"
  url: string;          // the public download address from getDownloadURL
  contentType: string;  // one of ALLOWED_IMAGE_TYPES
  size: number;         // bytes
  createdAt: number;    // Date.now() at upload, milliseconds
};
```

Firestore: collection `images`, document id = `ImageRecord.id`, fields exactly `name`, `storagePath`, `url`, `contentType`, `size`, `createdAt` (no `id` field is stored). Storage: object `images/<id>.<ext>` in the default bucket `thegoldenpothos-5b3a1.firebasestorage.app`, stored with the file's own bytes and `contentType`. Owner ID: the one place in `storage.rules` is `function ownerUid() { return 'REPLACE_WITH_OWNER_UID'; }`.

### 2.6 Non-functional notes

- Static export holds: no server, route or generated param is added; Firebase's Firestore and Storage modules are imported only by files that only `AdminPanel` reaches, and are created inside effects and handlers, never at module load or render (`next build` must not call them).
- The public pages stay Firebase-free; `admin-sign-in` E2E-13 still holds and E2E-53 checks the new strings too.
- The Storage emulator needs Java (21 installed; `cloud-storage-rules-runtime-v1.1.3.jar` is cached in `~/.cache/firebase/emulators/`). CI runs no e2e.
- Internal admin panel for one owner: no paging, no progress bar, no upload resume, no usage cap, no reference tracking.
- Tokens only for colour: `--surface-alt`, `--border`, `--border-strong`, `--foreground`, `--muted`, `--accent-rose`, `--radius-md`.

## 4. Verification mapping — SA

**Rules helpers (RH), used by E2E-01 to E2E-11 and copied into Steps 1 and 3.** Constants: `AUTH = "http://127.0.0.1:9099"`, `FIRESTORE = "http://127.0.0.1:8080"`, `STORAGE = "http://127.0.0.1:9199"`, `PROJECT = "thegoldenpothos-5b3a1"`, `BUCKET = "thegoldenpothos-5b3a1.firebasestorage.app"`, `DOCS = FIRESTORE + "/v1/projects/thegoldenpothos-5b3a1/databases/(default)/documents"`, `OBJ = STORAGE + "/v0/b/" + BUCKET + "/o"`. Rows E2E-01 to E2E-11 are plain Playwright tests with no page, inside one `test.describe` with `test.describe.configure({ mode: "serial" })`. Helpers:

- **signUp():** `POST AUTH/identitytoolkit.googleapis.com/v1/accounts:signUp?key=any-key` with JSON body `{"returnSecureToken": true}`; returns `{ uid: localId, token: idToken }`; retries up to 20 times, 500 ms apart, on a connection error.
- **RF(uid):** reads the repo file `firestore.rules`, replaces its single occurrence of `REPLACE_WITH_OWNER_UID` with `uid`, and sends `PUT FIRESTORE/emulator/v1/projects/thegoldenpothos-5b3a1:securityRules` with body `{"rules": {"files": [{"name": "firestore.rules", "content": <text>}]}}`; expects status 200. **RF(null)** sends the file text unchanged.
- **RS(uid):** the same for the repo file `storage.rules`, sent as `PUT STORAGE/internal/setRules` with body `{"rules": {"files": [{"name": "storage.rules", "content": <text>}]}}`; expects status 200. **RS(null)** sends the file text unchanged.
- **Who:** an account X means the storage header `Authorization: Firebase <X.token>` and the Firestore header `Authorization: Bearer <X.token>`; `"admin"` means `Authorization: Bearer owner` for both; signed out means no `Authorization` header.
- **put(name, type, bytes, who):** `POST OBJ?name=images%2F<name>` with header `Content-Type: <type>` and a body of exactly `bytes` bytes (the content is any bytes; an empty body for 0). **get(name, who):** `GET OBJ/images%2F<name>?alt=media`. **remove(name, who):** `DELETE OBJ/images%2F<name>`. **list(who):** `GET OBJ?prefix=images%2F`. **adminList():** the names in `items[].name` of `list("admin")` as an array of strings (a missing `items` is an empty array).
- **change(path, name, who):** `PATCH DOCS/<path>` with body `{"fields": {"name": {"stringValue": "<name>"}}}`; **read(path, who):** `GET DOCS/<path>`; **del(path, who):** `DELETE DOCS/<path>`; a read's stored value is `fields.name.stringValue` of the JSON response. **seedDoc(path, name):** `change(path, name, "admin")`, expects 200.

Object and document names are made from the row's `E2E-NN`, so no row depends on an empty store.

**Panel helpers (PH), used by E2E-19 to E2E-54 and copied into Step 3.** The rules helpers above are also defined in the file. Panel rows sit in one `test.describe` with `test.describe.configure({ mode: "serial", timeout: 60000 })`; the file has `test.use({ permissions: ["clipboard-read", "clipboard-write"] })`. `PANEL = "/bright-warm-greenhouse/"`; `IMG = "http://127.0.0.1:9199/v0/b/thegoldenpothos-5b3a1.firebasestorage.app/o/images%2F"`; the `request` fixture carries no sign-in, so it is "signed out".

- **adminClear():** with the admin header, delete every stored object named by `adminList()` (`DELETE OBJ/<encodeURIComponent(name)>`), then `GET DOCS/images?pageSize=300` and `DELETE FIRESTORE/v1/<name>` for the `name` of each returned document (a response with no `documents` has none).
