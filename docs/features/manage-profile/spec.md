## 1. Business analysis — BA

### 1.1 Purpose

The owner wants to keep the portfolio's profile current without opening the code. This feature gives the admin panel its first editor: choosing "Profile" in the section menu opens a form for the name, the headline, the about paragraphs, the photo, the email, the resume link and the social links. The owner changes them, presses "Save", reloads the panel and sees what was saved. The photo is either an uploaded image picked from the image library or a path to a file already in the site's repo, typed as text. The profile is one record; nothing is prefilled from today's site, so the first time the form is empty. This is also the first form of the panel, so the way it loads, checks, saves and reports failure is the pattern the later editors repeat. It does not change what visitors see on the public site (phase 2).

### 1.2 Actors & preconditions

- **Owner:** the single Google account whose Firebase user ID is in the rules and in the panel's owner constant. Saving works only for them once the ID is filled in.
- **Unfilled owner:** the owner signed in while the user ID is still the placeholder; the panel treats them as the owner for reading, shows the saving-off notice, and a save is refused by the rules (`admin-owner-only-access` D-06).
- **Other account:** any other signed-in Google account; the panel shows it the not-allowed screen and never the menu or the profile.
- **Visitor (signed out):** sees only the sign-in control.
- Preconditions met by hand (intent §7): the owner's user ID in the rules and the panel constant. No automated row depends on them; every row runs against the local emulators.

### 1.4 Data touched

One document of the database, `profile/main`, holding the name, headline, about paragraphs (a list of texts), photo (an uploaded image's public address or a repo path), email, resume link, social links (a list of label and address pairs) and the time of the last save. It is the only document the editor writes. The editor also reads the `images` collection (owner-only) to list uploaded images, and writes nothing there. The owner's own email address is typed content stored in the database; it is never read from the signed-in account and never committed. No browser storage is added.

## 2. Technical specification — SA

### 2.1 Approach

Three small modules and one component, mirroring the image library so the later editors can copy the shape. `src/lib/admin/profile.ts` is pure: the stored types, the exact messages, `checkProfile` (trim, validate, drop blank rows, report every refused field), `profileFromData` (tolerant reading of the stored record) and `photoSelection` (match a stored photo back to an uploaded image). `src/lib/firebase/profile.ts` reads and writes the one document `profile/main` with the Firestore client the image library already uses. `ProfileEditor` is a client component holding the form state; it reads the profile and the uploaded-image list once on mount, shows the form, validates through `checkProfile` on "Save", and writes through `saveProfile`. `AdminPanel` renders it for the "Profile" menu item on the allowed screen only and tells it whether saving is switched on, which picks the wording of a failed save. The rules need no change: `firestore.rules` already lets anyone read and only the owner write `profile/{id}`. Because the profile now carries an "Email" field, two earlier specs' source-level search for the word "email" skips the three files that hold that field, and the earlier placeholder test moves to a different menu item.

### 2.3 Data model

```ts
// src/lib/admin/profile.ts (pure: no firebase, no window)
export const PROFILE_COLLECTION: string;   // "profile"
export const PROFILE_DOC_ID: string;       // "main"
export type SocialLink = { label: string; url: string };
export type ProfileContent = {
  name: string;
  headline: string;
  about: string[];            // paragraphs, in order
  photo: string;              // an uploaded image's public address, or a repo path, or ""
  email: string;
  resumeLink: string;         // a web address, a path starting with "/", or ""
  socialLinks: SocialLink[];  // in order
};
export type ProfileErrors = {
  name?: string; headline?: string; email?: string; resumeLink?: string;
  socialLinks: (string | undefined)[];   // one entry per input link, in order
};
export type ProfileCheck = { ok: true; content: ProfileContent } | { ok: false; errors: ProfileErrors };
```

Firestore: document `profile/main`, fields exactly `name`, `headline`, `about` (array of strings), `photo`, `email`, `resumeLink` (strings), `socialLinks` (array of maps with string fields `label` and `url`) and `updatedAt` (a number: `Date.now()` at save, milliseconds). A save replaces the whole document. `profile` holds no other document.

### 2.6 Non-functional notes

- Static export holds: no server, route or generated param is added; the editor is a client component reached only through `AdminPanel`, and Firestore is touched only inside effects and handlers, never at import or render.
- Public pages stay Firebase-free (E2E-29).
- Internal admin panel for one owner: no autosave, no draft, no conflict check, no field-length limit; long text wraps.
- Tokens only for colour: `--surface-alt`, `--surface`, `--border`, `--border-strong`, `--foreground`, `--muted`, `--accent-rose`, `--radius-md`.
- Accessibility: every control is a native input, textarea, select or button reached by keyboard; each error is linked to its field with `aria-describedby`.

### Step 1 — Add the pure profile module and the profile read and write module, and move the two earlier "email" searches

- **Satisfies:** TS-01, TS-02, TS-03, TS-04
- **Depends on:** none
- **Files:**
  - add `src/lib/admin/profile.ts`
  - add `src/lib/firebase/profile.ts`
  - add `e2e/manage-profile.spec.ts`
  - change `e2e/admin-sign-in.spec.ts`

- **Reuse:** `src/lib/firebase/client.ts` → `getFirebaseDb(): Firestore` (memoized, browser only, connects the emulator on local hosts); nothing else.
- **Change:**
  - `src/lib/admin/profile.ts` is pure: it imports nothing from `firebase/*`, `@/lib/firebase` or the browser, so Playwright can import it by relative path. Exports: `PROFILE_COLLECTION: string` (`"profile"`); `PROFILE_DOC_ID: string` (`"main"`); `type SocialLink = { label: string; url: string }`; `type ProfileContent = { name: string; headline: string; about: string[]; photo: string; email: string; resumeLink: string; socialLinks: SocialLink[] }`; `type ProfileErrors = { name?: string; headline?: string; email?: string; resumeLink?: string; socialLinks: (string | undefined)[] }`; `type ProfileCheck = { ok: true; content: ProfileContent } | { ok: false; errors: ProfileErrors }`; `PROFILE_MESSAGES`, an object with the keys and exact texts: `nameRequired` "Name is required"; `headlineRequired` "Headline is required"; `emailInvalid` "Enter an email address like name@site.com"; `resumeInvalid` "Enter a web address or a path starting with /"; `socialInvalid` "Enter a full web address starting with https://"; `saved` "Profile saved"; `saving` "Saving…"; `loading` "Loading profile…"; `loadFailed` "The profile could not be loaded."; `imagesFailed` "The uploaded images could not be loaded."; `notSavedOff` "The profile could not be saved. Saving is not switched on yet."; `notSaved` "The profile could not be saved. Try again, and check that you are signed in as the owner."; `noProfile` "No profile has been saved yet."; `emptyProfile(): ProfileContent` returns a new object each call with every text `""` and `about` and `socialLinks` new empty arrays; `checkProfile(input: ProfileContent): ProfileCheck`; `profileFromData(data: unknown): ProfileContent`; `photoSelection(photo: string, images: readonly { id: string; url: string }[]): { imageId: string; path: string }`.
  - `checkProfile` works on trimmed texts. Name and headline must not be empty. Email, when not empty, must match `/^[^\s@]+@[^\s@]+\.[^\s@]+$/`. Resume link, when not empty, must match `/^https?:\/\/\S+$/` or `/^\/(?!\/)\S*$/`. Each social link whose trimmed label and address are not both empty must have an address matching `/^https:\/\/\S+$/`; a link whose label and address are both blank is ignored (not checked, not stored).
