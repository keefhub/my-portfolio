**Risks**

- R-1 (ListEditor default path drifts for Experience): the added props are read in three places; a wrong default would change the Experience screen. Likelihood low, cost medium. Carried: Step 2 Verify re-runs `manage-experience`; D-09.
- R-2 (a stale tab adds a project at a position another tab already used): two projects can then share a position and sort by id. Likelihood very low (one editor), cost low. Carried: Decision D-04 (last save wins) and Out of scope.
- R-3 (the `projects` collection also holds documents the owner-only-access spec wrote): `git grep -n "projects" -- e2e/admin-owner-only-access.spec.ts` finds only the emulator URL, so none today. Carried: `ownerSession` clears `projects` first and the reads are tolerant.

**Cleared**

- No new rule, index or emulator setting: `firestore.rules:26-29` already covers the collection; `projects` queries are whole-collection reads with client sorting, so no composite index.
- Public pages cannot carry the editor: it is imported only by `AdminPanel.tsx`, which only the panel route imports (`src/app/bright-warm-greenhouse/page.tsx`); E2E-18 checks it.
- No `<img>`, no `next/image`, no new CSS token, no new package.
