**Risks**

- **R-1 A test stand-in ships in the production bundle** (`src/lib/server/standin.ts`). Likelihood low, cost low: it runs only for a setting that starts with `stand-in:`; on Vercel the owner would have to type that by hand, and the result is a failing save, not an exposure. Carried as Decision D-7 and checked by E2E-10 (a `postgres://` string takes the real path).
- **R-2 The real SQL and the real library are never run by automation** (decomposition Open finding 1). The SQL is proven on PostgreSQL by a scratch script (SF-2, SF-6); the library path is proven only for failure (E2E-10). Whether a query succeeds through Supabase's pooler is unproven; Step 2's Stop-if and E2E-30 (the owner's SIT check) cover it. If `postgres` 4.1.1 misbehaves on the pooler, `3.4.7` takes the same calls (`postgres(url, options)`, `sql.unsafe`), and the owner reports it.
- **R-3 `ssl: "require"` does not verify the certificate** (the library's own note on `ssl` modes). The traffic is encrypted; checking Supabase's certificate chain needs a CA file in the repo. Accepted for a one-owner site; recorded as D-10.
- **R-4 The first-use schema race (SF-11).** Likelihood very low, cost one failed request.
- **R-5 `postgres` 4.x is new** (4.0.0 on 2026-10-29, 4.1.1 on 2026-11-11, from `npm view postgres time`). Pinned exactly. Likelihood medium that a quirk shows on the pooler, cost one SIT round (R-2 gives the fallback).
- **R-6 The gate is loosened for one directory** (`scripts/check-task.sh`). Likelihood low, cost low: the allowance is a prefix with a trailing slash, proved by running the `case` patterns: `src/app/api/admin/profile/route.ts` allowed, `src/app/api/administrator/route.ts` and `src/app/api/other/route.ts` still fail. E2E-01 re-proves it through the real script. A human should read this change in the pull request (D-14).
- **R-7 A paused Supabase project** shows "The profile could not be loaded." (accepted in intent §4). No keep-awake job.

**Cleared**

- The public build needs no setting: the route reads `process.env` only inside handlers (scratch build ran with none set).
- `GET`/`PUT` method handling: Next answers other methods with 405 by itself (scratch: `PUT` to a `GET`-only route → 405).
- No file other than the listed ones imports `src/lib/firebase/profile.ts` (`git grep -n "firebase/profile" -- src e2e` → `ProfileEditor.tsx:15` and the deleted spec).
- `src/lib/admin/profile.ts` has no imports and no `server-only`, so both the route's server module and the client editor can import it.
- `.github/workflows/pipeline.yml` needs no change: typecheck, lint and build need no setting.

**Before merge**

- E2E-06, E2E-07, E2E-09: a signed-out or other-account request is refused before any database call, also while the database is unreachable.
- E2E-10: the real `postgres` library, pointed at a closed port and at a blank setting, answers 503 and neither the response nor the server's captured log carries the address or the password marker.
- E2E-12 and E2E-13: the import graph keeps the database out of public pages.
- E2E-30 (manual, owner on SIT): sign in, open Profile, see "No profile has been saved yet.", save, reload and see the values. This is the only check of the real schema, the pooler and row level security.
