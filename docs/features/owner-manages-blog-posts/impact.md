## Domain map (Phase 2 result)

Entry points: `src/lib/admin/blogposts.ts` (record shape, validation, wording the earlier panel already had) and `src/app/components/admin/BlogPostsEditor.tsx` (the screen over the shared `ListEditor.tsx`).

**Risks**

- **R-1 The real SQL and library are never run by automation** (decomposition Open finding 1). Proven on PostgreSQL itself by SF-2; not proven through Supabase's pooler or its row level security role. Likelihood low, cost one SIT round. Carried as Decision D-17, E2E-36 (manual) and Step 1's Stop-if.
- **R-2 Anyone can read every published post, body included** (story Assumption 10): the published read is public by design. A draft that is switched to Published is public at once. Likelihood certain, cost none by intent; mitigated by the Draft default of a new post (BR-01b) and the owner's own checking before switching.
- **R-3 The sign-in spec's test title and loop are stale** (D-15): its title still says "each menu item shows its own not-available notice", its filtered loop is empty, and an added block asserts that no section shows the notice. A title line cannot be edited by this feature without breaking the gate's id bookkeeping. Likelihood certain, cost a misleading title until `retire-firebase` or a human renames it.
- **R-4 Tab divergence** (story Assumptions 14, 15): the last save wins; a stale tab that saves a deleted post is refused (never recreated). Accepted, D-12.
- **R-5 The schema step is shared** (SF-6): a pooler refusal of the new table statement would hide every database screen at once on SIT. Likelihood low, cost one SIT round.
- **R-6 A paused Supabase project** shows "The entries could not be loaded." and the published read answers 503 (accepted in intent §4). No public page reads it yet, so the public site is unaffected (BR-08e).
