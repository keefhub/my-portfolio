## 1. Business analysis — BA

### 1.1 Purpose

The owner writes, edits and deletes markdown blog posts in the panel's "Blog posts" screen, each as a Draft or Published post. Posts are kept in Supabase PostgreSQL, read and written only by the server. A post has a title, excerpt, date, slug, tags, a cover image (an image the owner uploaded in "Images", or a path to a file in the site's public files), cover alt text, a markdown body, a "Featured" setting and a status. The slug is the post's identity: unique, and fixed after the first save. This replaces the "Blog posts editor is not available yet." notice, the last one left. A post is not a plain list entry, so the feature keeps what the list slices built (the list screen, the browser list store, the owner check, the failure and log rules, the stand-in for tests, the image picker) and adds its own small store keyed by slug, two server routes and the screen's new store. Two server reads exist: the owner-only read of every post, and a public read of the published posts only. A draft can be read by nobody but the owner. Public pages keep reading the posts in the repository; moving them to the database is a later goal (intent §3).

### 1.2 Actors & preconditions

- **The owner**: signed in with the Google account whose verified email equals `ADMIN_EMAIL` (built by `owner-google-sign-in`). Sees the seven-item menu; every other item already opens a screen.
- **A signed-out visitor** and **a signed-in account that is not the owner**: refused on every request to the owner route, including one sent without the panel; they may read published posts, and only those, from the public read (story Assumption 10). A signed-out visitor can open an uploaded image at its public address (intent §5; OVERVIEW §2 item 7), which is what a post stores when the owner picks an uploaded image.
- **The database**: Supabase PostgreSQL (`SUPABASE_DB_URL`, built by `owner-edits-profile`), empty at first; nothing is imported (story Assumption 21).
- **The image list**: the owner-only list of uploaded images (`/api/admin/images/`, built by `owner-uploads-images`), read by the browser beside the posts.

## 2. Technical specification — SA

### 2.1 Approach

A post's identity is its slug and a save must fail when the slug is taken, which the generic list service (UUID ids, no uniqueness) cannot do, so posts get a small store of their own beside it. `src/lib/server/postSql.ts` holds nine closed SQL texts for one table `blog_posts` (`slug` primary key, a `status` column limited to `draft` or `published`, the other eight values in `data`); `src/lib/server/database.ts` gains five functions on its existing `run` wrapper (with their stand-in equivalents, writes one at a time) and runs the table's two schema statements in the shared schema step; `src/lib/server/postStore.ts` is the service (validation order, status mapping, ordering, the public projection). Two route files expose it: `/api/admin/blog-posts/` is owner-only and speaks the shape `createHttpListStore` already expects (`entries` of `{ id, position, content }`, the slug as the id), so the screen's store is the existing browser list store; `/api/admin/blog-posts/published/` is the one public read, selecting `published` rows in SQL and returning nine fields. It sits under `src/app/api/admin/` because the mechanical gate allows no other new route path and intent §4 approves no gate change (D-6). `src/lib/admin/blogposts.ts` gains `blogPostShape` (wrong kinds refused, extra properties dropped) and carries the slug and the draft flag in its wire shape. In the browser `BlogPostsEditor` swaps its Firebase store for `createHttpListStore("/api/admin/blog-posts/", blogPostFromData, blogPostToData)`, takes no props, keeps its fields, picker and Preview, and maps two new error classes of `listClient.ts` (a 409 and a 404) to the story's two messages. `AdminPanel` renders the screen and loses the notice, because no section lacks a screen. The Firebase blog store and the earlier emulator spec are deleted; seven earlier specs that expected the notice or the Firebase store are amended in test bodies; `CLAUDE.md` names the routes. The SQL was run on PostgreSQL by a throwaway script (impact.md SF-2); nothing in the suite runs it, so the owner's SIT check is the only test of the real database.

### 2.3 Data model

```ts
// src/lib/admin/blogposts.ts (existing types and functions stay; additions below)
type BlogPostContent = { title; excerpt; date; slug; tags: string /* "a, b" */; coverImage; coverAlt; body: string; featured: boolean; status: "Draft" | "Published" };
type BlogPostWire = { title: string; excerpt: string; date: string; slug: string; tags: string[]; draft: boolean; featured: boolean; coverImage: string; coverAlt: string; body: string };
blogPostShape(input: unknown): BlogPostContent | null;          // new
blogPostToData(content: BlogPostContent): BlogPostWire;          // gains slug (ten keys)
blogPostFromData(data: unknown, id?: string): BlogPostContent;   // slug from data.slug, else id, else ""

// src/lib/server/database.ts (new)
type StoredPost = { slug: string; published: boolean; data: unknown };
readPostRecords(onlyPublished: boolean): Promise<StoredPost[]>;
readPostRecord(slug: string, onlyPublished: boolean): Promise<StoredPost | null>;
insertPostRecord(record: StoredPost): Promise<boolean>;   // false when the slug is taken, nothing changed
updatePostRecord(record: StoredPost): Promise<boolean>;   // false when no such slug
deletePostRecord(slug: string): Promise<boolean>;         // false when no such slug

// src/lib/server/postStore.ts (new)
type PostEntry = { id: string; position: number; content: BlogPostWire };           // id is the slug, position is 0
type PublicPost = { title; excerpt; date; slug; coverImage; coverAlt; body: string; tags: string[]; featured: boolean };
type PostService = {
  list(): Promise<PostEntry[]>;
  get(slug: unknown): Promise<PostEntry | "invalid" | "not-found">;
  listPublished(): Promise<PublicPost[]>;
  getPublished(slug: unknown): Promise<PublicPost | "invalid" | "not-found">;
  add(body: unknown): Promise<{ ok: true; id: string } | { ok: false; reason: "invalid" | "slug-taken" }>;
  update(id: unknown, body: unknown): Promise<"updated" | "not-found" | "invalid">;
  remove(id: unknown): Promise<"deleted" | "not-found" | "invalid">;
```

**Table** `blog_posts` (created by the app, text in § 2.3 SQL below):

| Column | Type | Meaning |
| ------ | ---- | ------- |
| `slug` | `text primary key` | the post's identity; lowercase letters, digits and hyphens, checked by the server |
| `status` | `text not null`, `check (status in ('draft', 'published'))` | `published` exactly when the post's `draft` is false |
| `data` | `jsonb not null` | exactly `{ "title", "excerpt", "date", "tags": string[], "featured": boolean, "coverImage", "coverAlt", "body" }` as the service writes it, after trimming; no `slug` and no `draft` inside |
| `updated_at` | `timestamptz not null default now()` | set on every write |

**SQL** (exact texts, constants in `src/lib/server/postSql.ts`; no value is ever put into the text):

1. `create table if not exists blog_posts (slug text primary key, status text not null check (status in ('draft', 'published')), data jsonb not null, updated_at timestamptz not null default now())`
2. `alter table blog_posts enable row level security`
3. `select slug, status, data from blog_posts order by slug`
4. `select slug, status, data from blog_posts where status = 'published' order by slug`
5. `select slug, status, data from blog_posts where slug = $1`
6. `select slug, status, data from blog_posts where slug = $1 and status = 'published'`
7. `insert into blog_posts (slug, status, data) values ($1, $2, $3::text::jsonb) on conflict (slug) do nothing returning slug`
8. `update blog_posts set status = $2, data = $3::text::jsonb, updated_at = now() where slug = $1 returning slug`
9. `delete from blog_posts where slug = $1 returning slug`

**Owner route** `/api/admin/blog-posts/` (JSON; every response has `Cache-Control: no-store`):

| Method and query | Requester | Status | Body |
| ---------------- | --------- | ------ | ---- |
| `GET` | owner | 200 | `{ "entries": [ { "id": <slug>, "position": 0, "content": BlogPostWire } ] }` newest date first, ties by title then slug; `{ "entries": [] }` when empty |
| `GET ?slug=<slug>` | owner | 200 / 404 / 400 | `{ "entry": { "id", "position": 0, "content": BlogPostWire } }` (a draft included) / `{ "error": "not-found" }` / `{ "error": "invalid" }` for a slug that is empty or not lowercase letters, digits and hyphens |
| `POST`, body `{ "content": BlogPostWire, "position": <ignored> }` | owner | 200 | `{ "id": <slug> }` |
| `POST` of a slug that is stored | owner | 409 | `{ "error": "slug-taken" }`; nothing is stored or changed |
| `PUT ?id=<slug>`, body `{ "content": BlogPostWire }` | owner | 200 | `{ "updated": true }` |
| `DELETE ?id=<slug>` | owner | 200 | `{ "deleted": true }` |
| `PUT` or `DELETE` naming a slug with no stored post | owner | 404 | `{ "error": "not-found" }`; nothing is stored |
| any, invalid body, id or slug query | owner | 400 | `{ "error": "invalid" }`; nothing is stored |
| any | signed out | 401 | `{ "error": "not-signed-in" }` |
| any | signed in, not the owner (other account, or the owner's address with an unverified email) | 403 | `{ "error": "not-allowed" }` |
| any | owner, any database or unexpected failure | 503 | `{ "error": "unavailable" }` |

`PATCH` is not exported (the framework answers 405): posts are not reordered.

**Public read** `/api/admin/blog-posts/published/` (JSON, `no-store`, `GET` only, whoever asks; it never reads a cookie or a header):

| Query | Status | Body |
| ----- | ------ | ---- |
| none | 200 | `{ "posts": PublicPost[] }` published posts only, newest date first, ties by title then slug; `{ "posts": [] }` when none |
| `?slug=<slug>` | 200 | `{ "post": PublicPost }` when that post is published |
| `?slug=<slug>` of a draft or of a slug that is not stored | 404 | `{ "error": "not-found" }` (the same body for both) |
| `?slug=` empty or not lowercase letters, digits and hyphens | 400 | `{ "error": "invalid" }` |
| any database or unexpected failure | 503 | `{ "error": "unavailable" }` |

**Validation order** (the service): for `add`, the body is a plain object, then `blogPostShape(body.content)`, then `checkBlogPost`; the first failure is `invalid` and nothing is stored. For `update`, the id is a slug (`/^[a-z0-9-]+$/`), then the same three, then the checked slug must equal the id, else `invalid`. For `get`, `getPublished` and `remove`, the id or slug is a slug, else `invalid`. The owner check runs before all of it.

**`blogPostShape`**: returns `null` unless the input is a non-null, non-array object; `title`, `excerpt`, `date`, `slug`, `coverImage`, `coverAlt` and `body` must each be text or absent (absent becomes `""`); `tags` must be absent (becomes `""`) or a list whose elements are all text (joined with `", "`); `draft` must be absent (counts as `true`) or a boolean; `featured` must be absent (counts as `false`) or a boolean; anything else returns `null` for the whole input. The result is a new `BlogPostContent` (status `Published` only when `draft` is `false`); extra properties are dropped; it does not trim or validate (that is `checkBlogPost`).

**Stand-in file** (path = the part of `SUPABASE_DB_URL` after `stand-in:`): the key `blog_posts` holds an array of `{ "slug": string, "status": "draft" | "published", "data": <stored value> }` in insertion order; absent or not an array → empty; an element whose `slug` is not text or whose `status` is neither value is skipped when reading and kept when writing. Writing `blog_posts` keeps every other key (`profile`, `images`, `experience`, `projects`, `certifications`, `tech_categories`, `unreachable`). The existing rules for `unreachable: true`, an unreadable file or a file that is not a JSON object stay. Insert, update and delete of the stand-in run one at a time (a module-level promise chain), so two adds of one slug cannot both pass the free check.

**Row text** (the screen, not stored; unchanged from the earlier panel): the first line is the title (or the slug when the title is blank); below it `Slug: <slug>`, `Date: <formatDate(date)>` (or `Date: No date`) and `Status: <Draft|Published>`.

### 2.6 Non-functional notes
