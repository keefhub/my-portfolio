**Risks**

- **R-1 — a row fails against the unchanged preview.** The proofs above ran every row's central assertion, but not the exact tests the test author will write. Likelihood low, cost a spec revision (the Step's Stop-if names it). Carried: Decision D-02 and the Step's Stop-if.
- **R-2 — a repository-wide grep of an earlier spec matches the new file.** Likelihood low (SF-10 walks every grep), cost a failing earlier spec. Carried: Decisions D-13 and D-14, and the Step's Verify runs all eight earlier specs that search the tree or `e2e/` whole.
- **R-3 — the double click or keyboard rows are timing sensitive.** Likelihood low: the double activation is two synchronous DOM clicks inside one `evaluate`, and the keyboard rows use `focus()` then one key press, never a pointer position. Carried: Decision D-10.
- **R-4 — rows that characterise existing behaviour pass the first time they run.** Expected, not a defect; the gate may report "a test passed before the change" and raise the tier. Carried: Decision D-06 and the Step's Risk line.

**Cleared**

- The preview needs no environment variable and no new package: `markdownToHtml` imports only packages that are already dependencies (`src/lib/markdown.ts:1-8`), and `e2e/owner-manages-blog-posts.spec.ts` test 01 would fail on an added dependency.
- Public pages stay prerendered: no `src/app/**` file is touched, and `npm run build` (run by the gate) prints `/`, `/blog` and `/blog/[slug]` as static or SSG.
- Invariant 3 (no blog barrel in a client component): `PostPreview.tsx` imports `@/lib/markdown` and `@/app/components/blog/PostBody`, never `@/lib/blog` (read; the new source row pins it).
- Invariant 4 (UTC dates): the preview shows no date, so `formatDate` is not involved.
- `e2e/admin-content-panel-acceptance.spec.ts` still drives the preview with Firebase-era helpers: it already cannot pass and is retired by `retire-firebase`, so leaving it does not make anything new fail.
