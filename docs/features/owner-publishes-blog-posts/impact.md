**Risks**

1. Vercel's Data Cache may keep an entry across a code deploy, so a deploy does not always show everything saved so far (the intent accepts that a deploy does; it does not require it). Likelihood medium × cost low (the owner presses Publish). Carried: SF-6, OQ-3, D-05.
2. One entry holds every published post with its body; above about 2 MB the entry would not be kept and each visit would read the table. Likelihood very low (a personal blog) × cost low. Carried: D-06, OQ-4.
3. The first visit to a post address after a Publish or a deploy renders it (a markdown pass); a burst of first visits renders each once. Likelihood certain × cost negligible at this scale. Carried: D-07.
4. RSS and the sitemap list no post between this slice and the feeds slice. Likelihood certain × cost low (the pull request is one unit; the feeds slice is next). Carried: D-09, OQ-2, BR-27.
5. With JavaScript off a not-found post address is blank. Likelihood very low × cost low. Carried: SF-8, OQ-6.
6. If the database is unreachable when a renewed page is first requested after a Publish, the read throws (the outage slice owns keeping the last copy). Publish itself probes the database first (`loadProfile()`), which makes the window small. Carried: OQ-7 and Step 1's Stop-if.
7. The blog pages keep a footer without name or links and an "About" link even with no profile. Likelihood certain × cost low. Carried: D-14, OQ-1.
8. Twelve earlier spec files are edited; a missed assertion would show as a failing earlier test. Likelihood medium × cost low. Carried: Step 4 runs each named test by id and its Stop-if says to find any other with `git grep`; E2E-22 asserts the removals by text. `E2E-ACC-30` in the hosting acceptance spec snapshots `/blog/` byte for byte while specs run in parallel on one shared stand-in; once `/blog/` is a kept page another spec's Publish can renew it, so Step 4 retitles that test and drops the blog addresses from its comparison.
