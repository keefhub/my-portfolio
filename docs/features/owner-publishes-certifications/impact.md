**Risks**

- **R-1** (confirmed, certain, low cost): earlier tests expect a Certifications section on a page with no saved certification (`e2e/owner-publishes-profile.spec.ts:223`, `e2e/owner-publishes-experience.spec.ts:367` and `:423`, `e2e/retire-firebase.spec.ts:265`, `e2e/hosting-and-backend-migration-acceptance.spec.ts:1249`) and two public-source lists name the component (`e2e/retire-firebase.spec.ts:62`, `e2e/hosting-and-backend-migration-acceptance.spec.ts:1302`). They fail after Step 1 until Step 2 edits them. Carried: TS-07, Step 2, D-14.
- **R-2** (unproven, low likelihood, medium cost): if the page's certifications read fails during a regeneration while Publish's profile read succeeded, the framework's behaviour (keep the old copy, or fail the visit) is unproven here; the same open item exists for the profile and the Experience entries. Both reads go to one database through one client. Carried: Open Question OQ-1 and D-04; `site-survives-database-outage` proves the outage case for every section.
- **R-3** (confirmed, high likelihood, low cost): sibling slices edit `src/app/page.tsx`, `src/app/components/header.tsx` and the same earlier tests before this one is built, so a line number or an exact prop list would be stale. Carried: every Step says "search the file for the text" and fixes only the prop name `showCertifications` (spec § 2.5, D-14); the Step 1 Stop-if names the one premise (an existing optional prop in `header.tsx`).
- **R-4** (confirmed): `src/app/page.tsx` must keep exactly one occurrence of the word `revalidate` (the profile slice's E2E-21 counts it). Carried: TS-03 and Step 1's Change; E2E-16.
- **R-5** (confirmed, low): tests in `e2e/hosting-and-backend-migration-acceptance.spec.ts` and `e2e/owner-manages-*.spec.ts` save certifications and expect `/` to stay byte-identical. That stays true because saving does not renew the page. Checked by reading; the feature's gate at completion re-runs only this spec, so the Step 2 Verify names the amended earlier tests.
- **R-6** (cleared as a risk, kept as a note): the removed written-in certifications are lost from the code. The pull request must name the commit of Step 1 so the owner can re-enter them by hand (intent §2.4). Carried: D-13 and the report.
- **R-7** (confirmed, low): the blog pages keep the "Certifications" menu link when the section is hidden (the blog layout is untouched), as the About link does. Carried: D-10, R-3 in the spec's § 7.
