## 1. Business analysis — BA

### 1.1 Purpose

The Certifications section of the landing page still shows three certifications written into the code, while the owner already manages a Certifications list in the panel. This feature makes the section show the saved certifications, in the order the owner set, and only after the owner presses Publish. Saving, renaming, reordering or deleting changes nothing for visitors. With no saved certification the whole section and its "Certifications" menu link are hidden and nothing replaces them. The three certifications written into the code are deleted.

### 1.2 Actors & preconditions

- **Owner**: signed in with the Google account whose verified email is `ADMIN_EMAIL`; has the Certifications screen (built, `owner-manages-certifications`) and the Publish button (built, `owner-publishes-profile`).
- **Visitor**: anyone; never signs in; sees the last published copy of the landing page.
- Precondition: the Publish route and the kept landing page of `owner-publishes-profile` exist (built), and the Experience read pattern of `owner-publishes-experience` is built.

## 2. Technical specification — SA

### 2.1 Approach

`src/app/page.tsx` already is a kept page (`revalidate = false`) that reads the published profile and the Experience entries. It now also calls one new server read, `loadPublishedCertifications()`, and renders the whole `<section id="certifications">` only when the list is not empty, and tells the header whether to offer the "Certifications" link. The Publish route is not changed: its owner check, its single profile read and its single `revalidatePath("/")` already renew the whole page. A client-safe module `src/lib/publicCertifications.ts` holds the view type and a tolerant reader that turns stored records into certifications (it also cleans the two addresses); the server read adds the production-build guard and calls `readListRecords("certifications")`. The certifications component stops holding data and takes the list as props. The earlier checks that expect a Certifications section on an empty page, and the standing documents, are amended. This is the mechanism built in the profile and Experience slices; the blog pages do not change.

### 2.3 Data model

No stored data changes. The stored shape is the existing `CertificationContent` of `src/lib/admin/certifications.ts` (not imported by any public file): `{ name: string; icon: string; url: string }`, stored as the `data` of a record `{ id, position, data }` of the table `certifications`. `icon` is a path starting with `/` or an `http(s)` address (an uploaded image's address is its public Storage address); `url` is an `https://` address.

The new public view (`src/lib/publicCertifications.ts`):

```ts
export type PublicCertification = {
  name: string;
  icon: string; // "" when there is no usable badge address
  url: string;  // "" when there is no usable https credential address
};
export function publicCertificationsFrom(records: readonly { data: unknown }[]): PublicCertification[];
```

The server read (`src/lib/server/publicCertifications.ts`): `export async function loadPublishedCertifications(): Promise<PublicCertification[]>`.

The component: `export default function Certifications(props: { entries: PublicCertification[] })`. The header: `Header(props: { showAbout?: boolean; showCertifications?: boolean })`, both defaulting to true.

Publish response bodies are unchanged (`{"published":true}` 200, `{"error":"not-signed-in"}` 401, `{"error":"not-allowed"}` 403, `{"error":"unavailable"}` 503).

### 2.6 Non-functional notes

- Cost: one extra database read per renewal of the landing page; a personal site, one owner.
- Failure: database errors are reduced to a fixed message by `run()` in `src/lib/server/database.ts`; this feature adds no logging.
- Accessibility: each card stays one `<a>` (or, with no usable link, a block) whose text is the name; the badge keeps its alt text `<name> certification badge`; tokens only (`var(--…)`), no raw colour, no `dark:` variant.
- Security: nothing new reaches the browser except the certifications' own text and the two cleaned addresses; no secret, setting name or owner email.
- The framework renews `/` on the first visit after Publish, so "within a minute" is met by the first visit (earlier slices' SF-2).
