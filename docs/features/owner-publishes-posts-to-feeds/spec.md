## 1. Business analysis — BA

### 1.1 Purpose

The owner publishes posts in the panel, and the blog page already shows them after Publish. RSS and the sitemap still list no post (the earlier slice emptied them when it removed the repository posts). This feature makes both files list the published posts, newest first, and leave out drafts, renewed by the same Publish press that renews the blog page, with no code change and no new button. A saved but unpublished post stays out of both files until Publish. Both files stay kept pages: they keep the last good copy and only Publish or a deploy renews them.

### 1.2 Actors & preconditions

- **Owner**: signed in with the owner's Google account; saves posts (Draft or Published) in the panel and presses "Publish" (built).
- **Visitor, reader and search engine**: signed out; opens `/rss.xml` and `/sitemap.xml`.
- Preconditions: Publish already expires the cached published-posts read and renews the blog pages (built, `src/lib/server/publicPosts.ts` `refreshPublishedPosts`).

## 2. Technical specification — SA

### 2.1 Approach

The two feed files stop using an empty list and read the published posts through `loadPublishedPosts()`, the same cached snapshot the blog page uses, so they list exactly what the blog page lists in the same order and can never see a saved post before Publish. They stay `force-static`, so Vercel keeps the last good copy. Publish already expires that snapshot's tag, which renews a feed whose build copy was made from the snapshot. A build with no database setting makes the feeds from an empty list without the snapshot, so the tag alone would never reach them (impact.md, safety facts, level 4). `refreshPublishedPosts` therefore also renews the layout-type path of each feed after expiring the tag, and the Publish route itself needs no edit. The RSS builder escapes the CDATA terminator. The sitemap gives each post its date string as last-modified, so no time zone enters. Earlier specs that the change makes false are amended minimally, and the standing documents get additive edits.

### 2.3 Data model

Nothing is stored or migrated. The view type is the existing one (`src/lib/publicPosts.ts`):

```ts
type PublicBlogPost = { slug: string; title: string; excerpt: string; date: string /* "YYYY-MM-DD" */; /* tags, featured, cover, readingTime, content unused here */ };
```

`generateRssFeed(posts: { title: string; excerpt: string; date: string; slug: string }[], baseUrl: string): string` keeps its signature. The sitemap entry shape is Next's `MetadataRoute.Sitemap` item: `{ url: string; lastModified?: string | Date; changeFrequency?: ...; priority?: number }`.

### 2.6 Non-functional notes

- Sized for one owner and a handful of posts: one entry per post, no limit, no paging.
- Both routes are server files; no browser bundle gains database code. Neither reads cookies or headers, calls `auth()`, logs, or reads a setting.
- Renewal is immediate on Publish; the first request after it is answered with the new text (impact.md, level 4).
- A build with the database setting present reads the posts at build time; a failed read there fails that deploy and the previous one stays live (intent §2.4). A failed read while renewing makes the route throw and Vercel keeps the previous copy; keeping the files during an outage is proven in the outage slice.
