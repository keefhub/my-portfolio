## 1. Business analysis — BA

### 1.1 Purpose

The Projects section of the landing page still shows seven projects written into the code, while the owner already manages a Projects list in the panel. This feature makes the section show the saved projects, in the order the owner set, and only after the owner presses Publish. Saving, editing or reordering changes nothing for visitors. With no saved project the whole Projects section and its "Projects" menu link are not shown, and the rest of the page renders as before. The projects written into the code are deleted.

### 1.2 Actors & preconditions

- **Owner**: signed in with the Google account whose verified email is `ADMIN_EMAIL`; has the Projects screen (built, `owner-manages-projects`) and the Publish button (built, `owner-publishes-profile`).
- **Visitor**: anyone; never signs in; sees the last published copy of the landing page.
- Precondition: the Publish route and the kept landing page of `owner-publishes-profile` exist (built), and so does the Experience read this feature copies (built, `owner-publishes-experience`).

## 2. Technical specification — SA

### 2.1 Approach

`src/app/page.tsx` already is a kept page (`revalidate = false`) that reads the published profile and the Experience entries. It now also calls one new server read, `loadPublishedProjects()`, renders the `<section id="projects">` wrapper and the Projects component only when the list is not empty, and tells the header whether to keep its "Projects" link. The Publish route is not changed: its owner check, its single profile read and its single `revalidatePath("/")` already renew the whole page, projects included. A client-safe module `src/lib/publicProjects.ts` holds the view type and a tolerant reader that turns stored records into projects (including the rule that only `http(s)` links become links); the server read adds the production-build guard and calls `readListRecords("projects")`. The Projects component stops holding data, takes the projects as props, returns nothing for an empty list, drops empty parts of a card, and wraps long words. The earlier checks and the standing documents are amended where this switch makes them false. This is the mechanism built for the profile (D-01, D-04) and copied by Experience; nothing about the blog pages changes.

### 2.3 Data model

No stored data changes. The stored shape is the existing `ProjectContent` of `src/lib/admin/projects.ts` (not imported by any public file):
`{ title: string; shortDesc: string; description: string[]; tech: string[]; github: string; demo: string }`, stored as the `data` of a record `{ id, position, data }` of the table `projects`.

The new public view (`src/lib/publicProjects.ts`):

```ts
export type PublicProject = {
  title: string;
  shortDesc: string;
  description: string[];
  tech: string[];
  github: string; // "" or a trimmed http(s) address
  demo: string;   // "" or a trimmed http(s) address
};
export function publicProjectsFrom(records: readonly { data: unknown }[]): PublicProject[];
```

The server read (`src/lib/server/publicProjects.ts`): `export async function loadPublishedProjects(): Promise<PublicProject[]>`.

The component: `export default function ProjectCards(props: { projects: PublicProject[] })`. The header: `Header(props: { showAbout?: boolean; showProjects?: boolean })`, both defaulting to `true`.

Publish response bodies are unchanged (`{"published":true}` 200, `{"error":"not-signed-in"}` 401, `{"error":"not-allowed"}` 403, `{"error":"unavailable"}` 503).

### 2.6 Non-functional notes

- Cost: one extra database read per renewal of the landing page; a personal site, one owner.
- Failure: database errors are reduced to a fixed message by `run()` in `src/lib/server/database.ts`; this feature adds no logging.
- Accessibility: the card keeps `role="button"`, `tabIndex={0}`, `aria-label` and `aria-expanded`; tokens only (`var(--…)`), no raw colour, no `dark:` variant.
- Security: nothing new reaches the browser except the projects' own text; no secret, setting name or owner email; a stored link that is not `http(s)` never reaches an `href` (TS-01).
- The framework renews `/` on the first visit after Publish, so "within a minute" is met by the first visit (profile slice SF-2).
