**Risks**

- **R-1** (confirmed, certain, low cost): this feature changes `techstack.tsx`, which `e2e/retire-firebase.spec.ts` and `e2e/hosting-and-backend-migration-acceptance.spec.ts` require to equal the pre-migration commit. Both fail after Step 1 until Step 2 removes the file from their lists. Carried: TS-06, Step 2.
- **R-2** (unproven, low likelihood, medium cost): if the page's tech read fails during a regeneration while Publish's profile read succeeded, the framework's behaviour (keep the old copy, or fail the visit) is unproven here. The same open item exists for the profile and the entries (OQ-1 of both earlier specs). All reads go to one database through one client, so a split failure is not expected. Carried: Open Question OQ-1 and D-04; `site-survives-database-outage` proves the outage case for every section.
- **R-3** (confirmed, certain, low cost): with nothing saved, `section#experience` no longer exists on the page, and the "Experience" link disappears. Five earlier tests assume the opposite on a blank page: three in the Experience spec (the empty-page test, the delete-everything test and the "still lists techstack.tsx" test), the profile spec's empty-profile test, `E2E-44` of `e2e/retire-firebase.spec.ts` and `E2E-ACC-16` of the hosting acceptance spec. Carried: TS-06, Step 2 (these are the only specs that load `/` on a blank database and read these elements: checked with `git grep -n "section#\|Main navigation" -- e2e`).
- **R-4** (confirmed, low): `src/app/page.tsx` must keep exactly one occurrence of the word `revalidate` (the profile feature's check counts it). Carried: TS-03 and Step 1's Change.
- **R-5** (confirmed, low): `e2e/owner-manages-tech-stack.spec.ts` saves categories and expects `/` to stay byte-identical (two `request.get("/")` pairs). That stays true because saving does not renew the page. Checked by reading both pairs; re-run in the whole-spec runs of that feature, not in this one.
- **R-6** (cleared as a risk, kept as a note): the removed written-in categories and icon choices live only in git history. The pull request must name the commit of Step 1 so the owner can re-enter them by hand (story Assumption 6, intent §8). Carried: D-13 and the report. The nine icon files stay in `public/icons`, so the owner can re-enter each item with the same path.
- **R-7** (confirmed, low): the sibling slices (projects, certifications) are built after this one and edit the same page, the same header prop pattern and the same earlier checks. This spec avoids line numbers in Steps and names texts to search for; the earlier checks it edits are named by their titles.
