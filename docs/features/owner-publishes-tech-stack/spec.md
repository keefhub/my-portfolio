## 1. Business analysis — BA

### 1.1 Purpose

The Tech Stack block of the landing page still shows four categories and their icons written into the code, while the owner already manages tech categories and items in the panel. This feature makes the block show the saved categories and items, in the order the owner set, and only after the owner presses Publish. Saving changes nothing for visitors. A category with no items is not shown, and with no saved category the block is not shown at all. The block shares its place and its menu link with the Experience timeline, so the "Experience" link now shows only when the Experience entries or the Tech Stack have something to show, and the whole shared section is left out when both are empty. The categories written into the code are deleted.

### 1.2 Actors & preconditions

- **Owner**: signed in with the Google account whose verified email is `ADMIN_EMAIL`; has the Tech stack screen (built, `owner-manages-tech-stack`) and the Publish button (built, `owner-publishes-profile`).
- **Visitor**: anyone; never signs in; sees the last published copy of the landing page.
- Precondition: the Publish route and the kept landing page of `owner-publishes-profile`, and the Experience read of `owner-publishes-experience`, exist (built).

## 2. Technical specification — SA

### 2.1 Approach

`src/app/page.tsx` already is a kept page (`revalidate = false`) that reads the published profile and the Experience entries. It now also calls one new server read, `loadPublishedTechStack()`, and renders `TechStack` only when the list is not empty. The Publish route is not changed: its owner check, its single profile read and its single `revalidatePath("/")` already renew the whole page, categories included. A client-safe module `src/lib/publicTechStack.ts` holds the view types and a tolerant reader that turns stored records into categories (dropping what cannot be shown safely); the server read adds the production-build guard and calls `readListRecords("tech_categories")`. The `TechStack` component stops holding data, takes the categories as props, returns nothing for an empty list and wraps long names. The page renders the shared `section#experience` wrapper only when there are entries or categories, and tells the `Header` through a new optional prop whether to show the "Experience" link. Earlier checks that this switch makes false, and the standing documents, are amended. This is the mechanism proven in the profile and Experience slices; nothing about the blog pages changes.

### 2.3 Data model

No stored data changes. The stored shape is the existing `TechCategoryContent` of `src/lib/admin/techstack.ts` (not imported by any public file): `{ category: string; tools: { name: string; icon: string }[] }`, stored as the `data` of a record `{ id, position, data }` of the table `tech_categories`. The stored icon is either a path (`/…`) or an uploaded-image address.

The new public view (`src/lib/publicTechStack.ts`):

```ts
export type PublicTechTool = { name: string; icon: string };
export type PublicTechCategory = { category: string; tools: PublicTechTool[] };
export function publicTechStackFrom(records: readonly { data: unknown }[]): PublicTechCategory[];
```

The two icon patterns the view module repeats (copied from the panel's rule; the module must not import them):

```ts
const ICON_PATH = /^\/(?!\/)\S+$/;
const ICON_UPLOADED = /^https?:\/\/[^\s/]+\/storage\/v1\/object\/public\/images\/\S+$/;
```

The server read (`src/lib/server/publicTechStack.ts`): `export async function loadPublishedTechStack(): Promise<PublicTechCategory[]>`.

The component: `export default function TechStack(props: { categories: PublicTechCategory[] })`. The header: `Header(props: { showAbout?: boolean; showExperience?: boolean })`.

Publish response bodies are unchanged (`{"published":true}` 200, `{"error":"not-signed-in"}` 401, `{"error":"not-allowed"}` 403, `{"error":"unavailable"}` 503).

### 2.6 Non-functional notes

- Cost: one extra database read per renewal of the landing page; a personal site, one owner.
- Failure: database errors are reduced to a fixed message by `run()` in `src/lib/server/database.ts`; this feature adds no logging.
- Accessibility: each icon keeps a text alternative "<name> icon"; the heading levels (`h2` "Tech Stack", `h3` per category) are unchanged; tokens only (`var(--…)`), no raw colour, no `dark:` variant.
- Security: nothing new reaches the browser except the categories' own text and icon addresses; an address is passed on only when it matches one of the two patterns; no secret, setting name or owner email.
- The framework renews `/` on the first visit after Publish, so "within a minute" is met by the first visit (the profile slice's SF-2).
