## 1. Business analysis — BA

### 1.1 Purpose

The owner wants nothing of the removed backend left in the repository or the pipeline, the whole site checked once more, and the standing documents to describe the stack that is now in use: Vercel for hosting, Auth.js for the owner's Google sign-in, Supabase PostgreSQL and Supabase Storage for the panel's content. This is the last slice of the hosting-and-backend migration. It adds no screen and changes no public content: it deletes what the nine earlier migration slices left behind, proves that every public address still answers as before, that visitors can store nothing, that no secret value or owner email is in the repository, the built pages or the tests, that the pipeline for a pull request needs no service-account secret and no paid plan, and that the pull request lists every setting name the owner must set.

### 1.2 Actors & preconditions

- **Visitor** (recruiter, reader, search engine): reads public pages and files; stores nothing.
- **Owner** (Keith Lim): reads the pull request, sets every setting value in Vercel for Production and for SIT, and deletes the old cloud projects, secrets and GitHub environments afterwards (out of scope).
- **Pipeline** (GitHub Actions): runs on a pull request and on a push to `develop` or `master`.
- **Preconditions:** the nine migration slices (`owner-google-sign-in` to `owner-previews-blog-post`) are built (`git log` shows `docs(owner-previews-blog-post): mark implementation complete`, commit `c7ba7b2`); the public site is prerendered and the panel and `/api/*` run on the server (`.next/prerender-manifest.json` and `.next/app-path-routes-manifest.json`, read in Phase 2).
