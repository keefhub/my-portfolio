## 1. Business analysis — BA

### 1.1 Purpose

Every earlier slice of this goal moved one part of the public site from content written into the project to content read from the database. This slice is the closing check and the closing edit. It proves that nothing of the old content is left in the project, that no post file is left, that nothing was added to run the site, that no secret leaks, and that the rules which were not replaced still hold. It also rewrites the standing documents so that none of them still describes the old rules (pages prerendered at build time, blog content in files in the project), and it makes the pull request say that rules were rewritten and where the old text can be read from history.

### 1.2 Actors & preconditions

- Visitor: not signed in; opens the home page, the blog page, a post, the feeds.
- Owner: signed in with the owner's Google account; saves content in the panel and presses Publish.
- Reader of the repository (the owner, a reviewer): reads the project's files and the pull request.
- Precondition: every earlier slice of this goal is built and committed (`git log`, last commit `daeca1e docs(site-survives-database-outage): mark implementation complete`).

### 1.4 Data touched

- Content (profile, experience, tech stack, projects, certifications, posts): stored in the database by the earlier slices; this slice only reads it through the public pages in its checks, and it leaves the database empty and published after each check.
- Standing documents and the pull request template: text.
- No stored shape changes.

### 1.5 Edge cases & negative paths

- Old text hidden in a file type the scan skips (a binary): `public/resume.pdf` is a binary the owner links from the profile; the scan reads text files only. `[derived]` (see D-05, OQ-1)
- A post file renamed so a name pattern misses it: the check lists every tracked or untracked markdown file outside the allowed document folders, and any file in the project that starts with a front-matter block. `[derived]`
- A scan that cannot fail: each scan check first runs the same search on a throw-away repository that holds one planted match and expects it to be found. `[derived]`
- A draft post must be absent while a published post of the same visit is present (a positive control, so an empty page does not pass). `[derived]`
- A bare address (`/blog`) must redirect to the slashed form, not answer 404. `[in spec]` Sc7
- The empty database case is out of this story (the section slices and the outage story cover it). `[in spec]` A8
- Content saved but not published must not be asserted as visible: every visitor check publishes first and polls, because each kept page renews on its own first visit after Publish. `[derived]`

### 1.6 Out of scope

- An import or export tool for today's content; keeping the repo copy as a fallback; rewriting finished stories, specs or the decomposition documents; sanitising post HTML; scheduled posts, keep-awake job, publish history, rollback; any new dependency, setting, external or paid service (story Out of Scope).
- Deleting the owner's static files in `public/` (images, icons, the resume): they are assets, not text content (D-05).
- The manual check of the separate SIT and live databases (story A7, intent §7): the owner does it.

## 2. Technical specification — SA

### 2.1 Approach

The earlier slices already removed the content, so this feature adds no production code. It does two things. First, it edits the standing documents (README, Reference, CLAUDE, OVERVIEW, the repo profile) and the pull request template so they describe the new rules and the pull request flags the rewrite; the removing commits are recorded in `Reference.md`. Second, it adds one Playwright spec, `e2e/retire-repo-content.spec.ts`, that checks the end state once, repeatably: file scans (no old text, no post file, nothing added, no secret), and visitor flows against the built site (published content shows, a draft stays out, the standing rules still hold). The scans are the story's "check on the project's files and a build" (A4). Every scan proves it can fail with a planted control in a throw-away repository.
