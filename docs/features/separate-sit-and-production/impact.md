**Risks**

- **R1 — The web API keys cannot be read.** `npx firebase apps:sdkconfig WEB <appId> --project <projectId>` needs the owner's Firebase CLI sign-in. On this machine it works from PowerShell only (Git Bash resolves to another signed-in account that sees no projects), which Step 1 states. If it still fails, the implementer must stop, not write a placeholder or invent a key (a placeholder fails E2E-08). Likelihood medium in a cloud session, cost one stopped run. Carried to Step 1's Stop-if and Open Questions.
- **R2 — Rules shape breaks the first-occurrence replace.** A rules comment containing the literal `REPLACE_WITH_OWNER_UID`, or the SIT function placed first, would give the existing emulator specs a wrong owner. Likelihood low, cost high (eight specs fail in confusing ways). Carried to TS-04, E2E-17 and E2E-18.
- **R3 — Notice wording drifts.** `SavingOffNotice.tsx` still says "set OWNER_UID" and "replace REPLACE_WITH_OWNER_UID", while there are now two IDs and two placeholders per rules file. The owner replaces the first occurrence in each file for production and then the second for SIT. Likelihood certain, cost small (the owner reads the story's Deferred list); three existing specs lock the wording, so it stays (Assumption 13). Documented in Open Questions.
- **R4 — Filling in the IDs later breaks existing specs.** Once the owner fills in both IDs, the existing emulator specs' `text.replace(PLACEHOLDER, uid)` finds no placeholder, and `E2E-ACC-26` and `E2E-ACC-32` assert the placeholder is still in the rules. This hazard already exists with one ID; this feature does not widen it. Outside the five pre-approved rewrites, so not changed here. Documented in Open Questions.
- **R5 — A hosting-only `develop` deploy of rules fails for lack of a role.** The SIT deploy account needs the Firebase Rules Admin role (intent §7). The step then fails the run (Assumption 9). Cost: a red `develop` run until the owner grants the role. Carried to BR-18 and E2E-23.
- **R6 — Datastore-mode production database.** Production saves show the existing save-failure message until the owner moves it to Native mode (Assumption 12). Not testable here.
