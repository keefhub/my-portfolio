## Safety facts (blast radius)

Per `references/blast-radius.md`. Skipped entries: `e2e/site-survives-database-outage.spec.ts` (a test file nothing reads), `CLAUDE.md` and `Reference.md` (prose; their asserted strings are SF-9), `src/app/not-found.tsx` (one added link; SF-8 reads its callers).

All level-4 proofs ran in a throwaway Next 16.2.6 app (same installed `next`, `trailingSlash: true`, Turbopack build, `next start`) in the scratchpad `outage/` folder: a landing page, a blog list, a never-built post address (`generateStaticParams` returns none), `rss.xml` and `sitemap.ts` reading a file that can be switched to "down" (the read throws), with `revalidate = false` and the same `unstable_cache` and `revalidateTag` calls the repo uses. Nothing was written inside the repo.

**Risks**

1. A renewal that fails leaves the old copy but is not retried (SF-7): after a Publish that was followed at once by an outage, the saved change stays hidden until the owner presses Publish again once the database is back. Likelihood low (the window is the time between a successful Publish and the first visit) × cost low (one more press). Carried: Decision D-05, Open question OQ-1.
2. The first visit after Publish shows the previous copy once and starts the renewal (stale-while-revalidate); the second visit shows the new one. Likelihood certain × cost low. Carried: Decision D-04. The earlier publish specs poll after every `publish(` (counted with `grep -c`), so they hold; Step 3's regression run is the check.
3. A visitor request that finds the Data Cache empty (a cold or evicted entry) while the database is down gets an error page at a never-opened post address (SF-8). Likelihood very low (the build fills the entry; the entry is refreshed, never emptied, by Publish) × cost low. Carried: Decision D-08, OQ-2, E2E-13.
4. Hosting differences (SF-9): if Vercel dropped the previous copy on a failed renewal the story would be unmet on the real site. Likelihood low × cost high. Carried: E2E-12 (the owner's SIT outage check) and Step 2's Stop-if.
5. The shared stand-in database: this spec breaks it for a few seconds per test while other spec files run in parallel against the same file. Likelihood medium × cost low (a parallel spec's Publish would reply 503 and that one test fails). Carried: Decision D-11 (the break window is minimal and repaired in `finally`); OQ-3.
6. One cache entry per section holds the mapped values; the posts entry holds all post bodies (the earlier slice's 2 MB ceiling, still true). Likelihood very low × cost low. Carried: OQ-4 of the blog slice, unchanged.

**Cleared**
